9. สถาปัตยกรรม 6 ชั้นของระบบ TokenMem v3 ใน MicroCode IDE

ชั้นการบีบอัด (Optimization Layer) กลไกการทำงานเชิงวิศวกรรมใน TokenOptimizer.swift และ AgentService.swift ผลลัพธ์ที่ได้จริง
Layer 1: Prompt Prefix Cache Pinning แยก Static System Instructions และ Tool Schemas ไว้ที่ส่วนหัวคงที่ 100% และย้ายข้อมูลไดนามิก (เวลา, สถานะไฟล์) ไปท้ายข้อความ เพิ่มอัตรา Prompt Cache Hit สูงถึง 84.0% (ลดต้นทุน Input 75–90%)
Layer 2: Dynamic Tool Schema Pruning วิเคราะห์ Intent ของคำสั่งผู้ใช้และส่งเฉพาะ JSON Schema ของ Tool ที่เกี่ยวข้องในรอบนั้น แทนการแนบ Tool ทั้งหมดทุกครั้ง ลดขนาด Tool Schema Overhead ลง 62% ต่อรอบ
Layer 3: Observation Masking (Turn Decay) ผลลัพธ์ของ Tool ที่เก่าเกิน 2 รอบ (file_read, grep_search, Build Logs) จะถูกแทนที่ด้วย Compact Reference Summary พร้อมรหัสอ้างอิง ป้องกันปัญหา Context Bloat จากผลลัพธ์คำสั่งยาวๆ ได้ 70–85%
Layer 4: AST Skeletonizer & Line-Range Slicing ไฟล์ประกอบบริบทที่ไม่ได้ถูกแก้ไขโดยตรงจะถูกสกัดเฉพาะโครงสร้างคลาสและฟังก์ชัน (Signatures) แทนการส่งเนื้อหาโค้ดทุกบรรทัด ลดขนาดโทเคนของไฟล์อ้างอิงลงเฉลี่ย 78%
Layer 5: Structured State Checkpointing เมื่อประวัติแชทยาวเกินงบประมาณ ระบบจะบีบอัดรอบเก่าเป็น StructuredStateCheckpoint (Goal, Modified Files, Decisions, Next Steps) รักษาความแม่นยำของงานต่อเนื่องโดยไม่เกิด Context Drift
Layer 6: Sub-Agent Context Isolation แยกงานค้นหาขนาดใหญ่ลงใน Sub-Agent ที่มี Context Window แยกอิสระ และส่งกลับเฉพาะข้อสรุปสั้นๆ เข้าสู่หน้าต่างหลัก หน้าต่างแชทหลักสะอาดและตอบสนองไวตลอดการทำงาน

11. ข้อเสนอแนะและแผนพัฒนาต่อยอด 5 ด้าน (Engineering Roadmap for v2.5.33+)

จากการวิเคราะห์เชิงลึกหลังเสร็จสิ้นการทำ Benchmark พบว่า MicroCode ยังมีศักยภาพในการลดเวลา Cold-Start ลงไปสู่ระดับ 250–300 ms และลดการใช้หน่วยความจำพื้นฐานลงสู่ระดับ 140–155 MB ด้วยแผนงานวิศวกรรม 5 ข้อดังต่อไปนี้:

  1. ระบบ Persistent Disk Cache สำหรับ CLI Ecosystem Discovery (ลด Background RAM Spike ~260 MB): บันทึกผลลัพธ์การค้นหาโมเดลจาก CLI ภายนอก (agy models, opencode models, ollama list) ลงไฟล์ Cache บนดิสก์พร้อมตรวจสอบค่า mtime ของไฟล์ไบนารี เพื่อหลีกเลี่ยงการแตกโปรเซส agy และ opencode ซ้ำทุกครั้งที่เปิดโปรแกรม
  2. การทำ Lazy Service & View Instantiation ใน ContentView และ AIAgentView (ลด Cold-Start ลงอีก ~150 ms): เปลี่ยนการผูก @ObservedObject กับ Singleton Services ของแผงฟีเจอร์รอง (เช่น Collaboration, Team Tasks, Mobile Device Dock, Preview Bridge) ให้สร้างอินสแตนซ์เฉพาะเมื่อผู้ใช้กดเปิดแผงนั้นจริง
  3. การแยกดัชนีรายการแชท (chats_index.json) ออกจากไฟล์เนื้อหาข้อความเต็มใน AgentService: อ่านเฉพาะข้อมูลหัวข้อแชทขนาดเล็กเพื่อแสดงรายการบน Sidebar ทันทีภายในเวลาไม่ถึง 1 มิลลิวินาที และโหลดประวัติข้อความเต็มเฉพาะห้องแชทที่ผู้ใช้กำลังเปิดใช้งาน
  4. ระบบ Auto-Hibernation สำหรับ WKWebView ในแผง Live Preview และ IDE Browser (คืน RAM ~150 MB): เมื่อผู้ใช้พับเก็บแผง Web Preview เกิน 2 นาที ให้ระบบปลดโปรเซส WebKit.WebContent ออกจากหน่วยความจำโดยบันทึก URL และตำแหน่ง Scroll ไว้ และกู้คืนอัตโนมัติเมื่อเปิดแผงอีกครั้ง
  5. การผสาน Built-in MCP Server เข้าสู่ Native Swift / Rust In-Process 100%: ย้ายการประมวลผลเครื่องมือพื้นฐานจาก mcp-server.py เข้าสู่ AgentToolBox.swift และไลบรารี libmicrocode_core.dylib โดยตรง เพื่อตัดภาระการรัน Python Interpreter สำหรับเครื่องมือภายในทั้งหมด
การรับรองความถูกต้องของข้อมูลและผลการทดสอบ (Official Engineering Certification)

ชุดทดสอบซอร์สโค้ด (benchmarks/run_ide_benchmarks.py, benchmarks/window_probe.swift) และไฟล์ข้อมูลดิบ (benchmarks/results/ide_benchmark_results.json) ได้รับการบันทึกไว้ในคลังซอร์สโค้ดหลักของบริษัท ดอทมินิ จำกัด เพื่อการตรวจสอบและทำซ้ำ (Reproducibility) ได้ทุกเมื่อ
